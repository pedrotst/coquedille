# PLAN — Port Coquedille to Rocq 9.x / MetaRocq

Goal: make this repo — a translator from quoted Coq terms to Cedille syntax,
last built against **Coq 8.9.1 + MetaCoq (template-coq) + coq-ext-lib** — build
and pass its test suite on **Rocq 9.2.0 + MetaRocq 1.5.1 + coq-ext-lib 0.13.1**,
with the same architecture: `theories/` compiles, `tests/run_tests.sh` extracts
the translator to Haskell, runs it on quoted test programs, and diffs the
pretty-printed Cedille output against `tests/*/expected`.

## Ground rules

- **Never build this project in the `gadt-autosubst` switch** (it pins Rocq
  9.0.x for a different project). Use the dedicated `coquedille` switch, always
  via `opam exec --switch=coquedille -- ...` or after `eval $(opam env --switch=coquedille)`.
- `Makefile` is generated by `coq_makefile` from `_CoqProject` (see
  `init_repo.sh`). Regenerate it; never hand-edit. The repo's habit is to keep
  the generated Makefile checked in — preserve that.
- `tests/*/expected` files are the spec. Change one only when the difference is
  explainable (see Phase 5) and record the reason in the commit message.
- `theories/Autosubst` does not exist here; that rule from the sibling project
  does not apply. There is no generated Coq code in this repo.

## Phase 0 — Toolchain

Version constraints that force the target:

- `coq-ext-lib 0.13.1` supports Rocq 9 only via `coq-core >= 9.2` + `rocq-stdlib`
  (0.13.0 caps at `coq-core < 9.2`).
- `rocq-metarocq-utils 1.5.1+9.1` pins `rocq-core < 9.2`, so on 9.2 you need
  `1.5.1+9.2`. MetaRocq pulls in `rocq-equations >= 1.3.1` automatically.
- Hence: **Rocq 9.2.0, rocq-metarocq-template 1.5.1+9.2, coq-ext-lib 0.13.1**.

Setup (already done — the `coquedille` switch exists):

```bash
opam switch create coquedille ocaml-base-compiler.5.3.0 \
  --repos=rocq-released=https://rocq-prover.org/opam/released,default=https://opam.ocaml.org
opam install --switch=coquedille rocq-core.9.2.0 rocq-stdlib rocq-metarocq-template.1.5.1+9.2 coq-ext-lib
```

The `rocq-released` repo is required; the default opam repo does not carry
these versions. The test harness additionally needs `ghc` on `PATH`
(ghcup's 9.6.7 works).

## Phase 1 — Namespaces and build system

| Old | New |
|---|---|
| `Require Import MetaCoq.Template.Ast.` etc. | `From MetaRocq.Utils Require Import utils.`<br>`From MetaRocq.Common Require Import BasicAst Kernames.`<br>`From MetaRocq.Template Require Import Ast AstUtils.` |
| `Require Import MetaCoq.Template.All.` | `From MetaRocq.Template Require Import All.` |
| `Quote Recursively Definition x := t.` | `MetaRocq Quote Recursively Definition x := t.` |
| `Require Import Coq.Strings.String.` (etc.) | `From Stdlib Require Import Strings.String.` |
| `Require Coq.extraction.Extraction.` | `From Stdlib Require Extraction.` |

Bare `Require Import String.` / `List.` (as in `Ast.v`, `Hardcoded.v`,
`PrettyPrinter.v`) still resolve against `rocq-stdlib` by suffix, so they did not
block the port — but Rocq 9 deprecates loading Stdlib without a prefix, and they
have since been changed to `From Stdlib Require Import ...` to silence it. The
build is now warning-free on that count. `_CoqProject` is unchanged. Rebuild the Makefile with the
9.2 `coq_makefile` (`./init_repo.sh` does both steps); the large Makefile diff
in the tree is exactly this regeneration.

## Phase 2 — MetaCoq → MetaRocq API migration map

All of this lands in `theories/DenoteCoq.v` (the only theory file that touches
the MetaRocq AST). The current tree already implements it; treat this table as
the checklist if anything must be redone.

1. **Bytestrings.** MetaRocq identifiers are `bytestring.String.t` and MetaRocq
   globally opens `bs_scope`. Strategy: keep the whole Ced pipeline on Rocq's
   `string`; convert once at the boundary with
   `Definition of_bs := bytestring.String.to_string`. Import
   `From Stdlib Require Import Strings.String` **after** the MetaRocq imports so
   the unqualified `string` is Rocq's, add `Local Open Scope string_scope`, and
   qualify ambiguous operations (`Stdlib.Strings.String.eqb`, `.length`,
   `.substring`) where needed.
2. **Kernames.** `kername` was a dot-separated `string`; it is now
   `modpath * ident`. Replace string surgery with:
   - qualid of a kername: `snd kn` (+ `of_bs`);
   - full name for messages: `string_of_kername`;
   - equality: `eq_kername`;
   - recognising stdlib constants (`False_ind`, `nat_rect`, …): match by
     **suffix** of `string_of_kername` (helper `kername_is`), because the
     stdlib prefix changed from `Coq.` to `Corelib.`/`Stdlib.` and hardcoding
     either would be brittle.
3. **Binder names.** Binders are `aname := binder_annot name` (adds relevance).
   Unwrap with `binder_name` (helper `aname_to_name`) everywhere a `name` was
   consumed (`dname`, `decl_name`, `tLambda`/`tProd` binders).
4. **`tCase` changed shape.** See Phase 3 — this is the only structural rework.
5. **Inductive declarations.** `ind_ctors` entries are now `constructor_body`
   records: use `cstr_name`, `cstr_type` (old triple `(ident * term * nat)`).
   `lookup_mind_decl` comes from `AstUtils`. `ind_params` is still a `context`
   of `context_decl` (`decl_name`, `decl_type`).
6. **Constant bodies.** `constant_body` gained `cst_relevance`; rebuild records
   field-by-field where they are mapped over.
7. **Global environment.** `program := global_env * term`, but `global_env` is
   now a record `{ universes; declarations; retroknowledge }`. Take
   `declarations`, and `rev` it before denoting: it lists the most recent
   declaration first, while the translator folds oldest-first.
8. **Universes/sorts.** Universe instances are `Instance.t`; sorts are built
   with `Sort` (`Sort.type1` as a dummy). The translator only pattern-matches
   `tSort _`, so little else changes.
9. **New primitive constructors.** `term` gained `tInt`, `tFloat`, `tString`,
   `tArray`. Add `raise "... not implemented yet"` arms in `denoteType` /
   `denoteTerm` (and a traversal arm for `tArray` in `expand_cases`) so the
   matches stay exhaustive.
10. **ext-lib.** `Import MonadNotation` and the monad-transformer stack
    (`stateT`/`readerT`/`eitherT`/`ident`) are unchanged in 0.13.1. Typeclass
    instances need `#[global]` to silence deprecation.

## Phase 3 — Re-inflating `tCase` (the one real design problem)

Old template-coq stored a match as `tCase (ind, npars) motive discr brs` where
the motive and every branch were explicit `tLambda` chains, and the translator
was written against that. Rocq 9 stores a compact form:
`tCase ci p discr brs` with `p : predicate term` (`pparams`, `puinst`,
`pcontext`, `preturn`) and `brs : list (branch term)` (`bcontext`, `bbody`) —
binder *names* only; their types live in the inductive declaration.

Chosen solution (implemented as `expand_cases` in `DenoteCoq.v`): a **pre-pass
over the whole global environment** that rebuilds the old representation —

- motive: λ-abstract `preturn` over `pcontext`, taking the index types from the
  inductive's arity (`ind_type` instantiated with `pparams` via `inst_prods`)
  and typing the final binder as the inductive applied to params + indices
  (`discr_type`);
- branches: λ-abstract each `bbody` over `bcontext`, taking argument types from
  the constructor type (`cstr_type` with the inductive block substituted via
  `inds` and params instantiated).

Rationale: doing this as a separate pass keeps `denoteType`/`denoteTerm`
structurally recursive (they only descend into genuine subterms, never into a
motive synthesised mid-recursion), so no termination hacking is needed. The
branches indexed with `mapi` + `nth_error (ind_ctors idecl)` rather than a zip,
for the same reason. `denoteCoq` runs `expand_env` before denoting.

## Phase 4 — Extraction and the Haskell test harness

`tests/Extraction.v`:

- `MetaRocq Quote Recursively Definition` for every test case; vector case uses
  `Vectors.Vector.t` via `From Stdlib Require Import Vectors.Vector`.
- Keep the old `Extract Inductive/Constant` directives, retargeted at
  `Stdlib.Strings.String.string` / `.string_dec` / `.eqb`.
- **New:** MetaRocq drags in Equations' `Signature` machinery, and Equations'
  `sigma` extracts to `( * )` — valid OCaml, invalid Haskell. Fix:
  `Extract Inductive Equations.Init.sigma => "(,)" [ "(,)" ].` (with
  `Extract Inductive prod => "(,)" [ "(,)" ].` alongside).

`tests/run_tests.sh`:

- The old sed hack deleting `eqb_spec0` is obsolete — drop it.
- **New:** extracted code contains `type Any = GHC.Base.Any`; `GHC.Base.Any` is
  poly-kinded, which makes the kind variables of the extracted monad stack's
  type synonym uninferrable. Since every value of that type goes through
  `unsafeCoerce`, pin it: `sed 's/^type Any = GHC.Base.Any$/type Any = ()/'`.
- The rest of the pipeline (inject `Data.Bits`/`Data.Char`/`GHC.IO.Encoding`
  imports, append `main`, compile with ghc, `cmp` against `expected`) is
  unchanged.

`theories/Extraction.v` (the standalone `Recursive Extraction denoteCoq` smoke
test) gets the same namespace fixes.

## Phase 5 — Expected-file policy

Regenerated output may differ from `expected` for reasons that are *not* bugs:
Rocq 9's stdlib gives different **binder names** inside standard lemmas (e.g.
`eq_ind`'s proof binders are now `eq_refl'`/`a` instead of `f`/`y`). Policy:

- A diff that is pure α-renaming (binder names only, same structure) → update
  `expected`, note the cause in the commit message. `tests/zeroneqS/expected`
  is the one case that needed this.
- Any structural diff (different term shape, missing/extra commands) → treat as
  a port bug; investigate before touching `expected`.

## Landmines

- Forgetting the `rocq-released` opam repo → the 9.2/MetaRocq packages simply
  don't resolve.
- Importing Stdlib strings *before* MetaRocq → `string` silently means
  bytestring, and errors surface far from the cause. Keep the import order and
  the boundary conversions (`of_bs`) as in the current `DenoteCoq.v`.
- Matching stdlib kernames by full name or `Coq.` prefix → hardcoded terms
  (`False_ind`, `nat_rect`, `list_ind`, `JMeq_rect`) silently stop being
  substituted and tests fail with structural diffs. Use suffix matching.
- `global_env.declarations` is newest-first; forgetting the `rev` makes
  everything reference-before-declaration in the Cedille output.
- Extracted Haskell failing with kind errors on `Any`, or syntax errors on
  `( * )` → the two Phase 4 fixes; both live in `tests/` and are easy to lose
  when regenerating.
- Running any build in the wrong switch (`gadt-autosubst` pins Rocq 9.0; the
  shell default may point at yet another). Always go through
  `opam exec --switch=coquedille --`.
